# נדרים – מדריך למשתמש

מערכת לניהול נדרים, תרומות והוצאות של בית כנסת. יישום שולחני ל-Windows, עובד ללא אינטרנט, כל הנתונים נשמרים במחשב שלך בלבד.

---

## 1. התקנה

1. הורד את הקובץ `nedarim-setup-<גרסה>.exe`.
2. הפעל אותו. Windows יציג אזהרת SmartScreen ("Windows protected your PC") – זה קורה לכל תוכנה חינמית שאין לה תעודת חתימה בתשלום. לחץ **More info → Run anyway**.
3. בחר תיקיית התקנה (ברירת המחדל תקינה) והמשך. נוצר קיצור דרך בשולחן העבודה ובתפריט התחל.

**אין צורך ב-Node, ב-npm או בכל תוכנה נוספת.** ההתקנה כוללת הכול.

### היכן נשמרים הנתונים

```
C:\Users\<שם המשתמש>\AppData\Roaming\nedarim\
├── nedarim.db          בסיס הנתונים – כל החברים, הנדרים, התשלומים והקבלות
├── receipts\           קובצי ה-PDF של הקבלות
├── attachments\        קבצים שצורפו להוצאות
└── backups\auto\       הגיבויים הפנימיים
```

הסרת ההתקנה **אינה מוחקת** את התיקייה הזו. שדרוג לגרסה חדשה שומר את כל הנתונים.

---

## 2. הפעלה ראשונה

היישום נפתח עם בסיס נתונים ריק ועם פס צהוב בראש המסך שמפנה להגדרות.

### מה חובה להגדיר לפני העבודה

לשונית **הגדרות → הגדרות**:

| שדה | למה זה משנה |
|---|---|
| **שם בית הכנסת** | מודפס בראש כל קבלה ובכותרת כל דוח. שדה חובה. |
| יישוב, כתובת, טלפון | מודפסים על הקבלה |
| מספר עמותה | מודפס על הקבלה, אם יש עמותה רשומה |
| לוגו, תמונת חתימה | תמונות שמופיעות על הקבלה |
| **חודש תחילת שנה כספית** | קובע לפי מה נחתכות השנים במאזן ובדוחות |
| סף אישור מנהל לזיכוי | זיכוי מעל הסכום הזה ידרוש הרשאת מנהל |
| גודל נייר לקבלה | A5 או A4 |
| **תיקיית ארכיון הקבלות** | לאן נשמרים קובצי ה-PDF. ריק = תיקיית הנתונים של היישום |

לשונית **הגדרות → מונים**:

- **המספר של הקבלה הבאה** – אם בית הכנסת כבר הנפיק קבלות בפנקס ידני או במערכת קודמת, קבע כאן את המספר שממנו להמשיך. **אפשר להגדיר רק לפני הפקת הקבלה הראשונה**, ורק כלפי מעלה. אחרי שהופקה קבלה, המספרים נעולים – זו דרישה חשבונאית.

לשונית **הגדרות → רשימות ערכים**:

- פרשות ואירועים, אמצעי תשלום, סוגי תרומה וקטגוריות הוצאה. אפשר להוסיף ולשנות שם, ולהשבית ערך שכבר לא בשימוש. **אי אפשר למחוק** ערך שכבר משויך לרשומה – אחרת רשומות ישנות היו נשארות בלי קטגוריה.

## 3. עבודה יומיומית

### מסך ראשי
תמונת מצב: יתרות, חייבים גדולים, תשלומים שממתינים לקבלה, וקיצורי דרך לרישום נדר או תשלום.

### חברים
רשימת החברים עם היתרה של כל אחד. לחיצה על שורה פותחת את **הכרטיסייה** – כל התנועות של החבר לפי סדר, עם היתרה המצטברת.

### נדרים ותשלומים
- **נדר** = חיוב. נרשם על חבר, בתאריך, תחת פרשה או אירוע.
- **תשלום** = זיכוי. אפשר להפיק קבלה בו-במקום.
- **זיכוי** = ביטול חיוב (טעות, ויתור). מתועד עם סיבה.

### קבלות
- מספר הקבלה מוקצה **פעם אחת בלבד** ואינו משוחרר לעולם, גם אם הקבלה בוטלה.
- **קבלה אינה ניתנת לעריכה.** תיקון נעשה בביטול הקבלה והפקת חדשה. הביטול נשמר עם סיבה.
- הדפסה חוזרת מסומנת כ"העתק".
- מסך **ספר קבלות** מציג את כל הקבלות עם בדיקת רציפות מספרים.

### תרומות והוצאות
תרומות (עם או בלי שיוך לחבר) והוצאות עם קטגוריה, ספק וקובץ מצורף.

### מאזן ודוחות
מאזן חודשי ושנתי, ודוחות שאפשר לייצא ל-Excel או ל-CSV.

### בכל טבלה במערכת
- לחיצה על **כותרת עמודה** ממיינת (עולה → יורד → ללא). המיון נשמר לכל מסך בנפרד.
- **סרגל סינון** מתכווץ עם השדות הרלוונטיים לאותו מסך.
- **סקשן סטטיסטיקה** מתכווץ מעל הטבלה, שמחושב תמיד **לפי הסינון הפעיל** – לא על כל הנתונים.

## 4. אבטחה

ברירת המחדל: היישום נפתח ישירות, בלי סיסמה. זה מתאים לגבאי יחיד על מחשב אישי.

**אם המחשב משותף**, הדלק בהגדרות → מערכת:

| הגדרה | משמעות |
|---|---|
| **לדרוש התחברות בסיסמה** | מסך כניסה בפתיחת היישום |
| **נעילה אוטומטית (דקות)** | המסך ננעל אחרי חוסר פעילות. 0 = ללא נעילה |

בהתחברות הראשונה, המשתמש `admin` עדיין בלי סיסמה – היישום יבקש לקבוע אחת מיד.

### משתמשים (הגדרות → משתמשים)

שלושה תפקידים: **מנהל** (הכול), **פקיד** (רישום שוטף), **צפייה בלבד**.

- משתמש **מושבת ולא נמחק**, כדי שרשומות יומן הביקורת שלו יישארו עם שם.
- תמיד חייב להישאר לפחות מנהל פעיל אחד – המערכת לא תיתן להשבית את האחרון.
- מנהל יכול לאפס סיסמה של אחרים; כל אחד יכול לשנות את שלו.

### יומן ביקורת

לשונית **יומן ביקורת**: כל שינוי בנתון כספי – מי, מה, מתי, ומה היה הערך לפני ואחרי. היומן **אינו ניתן לעריכה או למחיקה מתוך היישום**. ניתן לסנן ולייצא ל-Excel.

## 5. גיבוי ושחזור

הגדרות → **גיבוי ושחזור**.

### גיבוי

| כפתור | מה הוא עושה |
|---|---|
| **גיבוי עכשיו** | גיבוי לתיקייה הפנימית `backups\auto` (נשמרים 30 האחרונים) |
| **גיבוי לתיקייה חיצונית** | גיבוי ל-USB / תיקיית ענן. **זה הגיבוי שבאמת מציל** |

כל גיבוי כולל את בסיס הנתונים, קובצי הקבלות, הקבצים המצורפים, וקובץ `manifest.json` עם חתימת SHA-256 ועם המספרים של אותו רגע (כמה חברים, כמה קבלות, סך היתרות).

המערכת תזכיר לגבות לתיקייה חיצונית כשעברו יותר מ-7 ימים (ניתן לשינוי בהגדרות).

> **גיבוי על אותו מחשב אינו גיבוי.** דיסק שנשרף לוקח איתו גם את `backups\auto`. גבה לזיכרון נייד או לתיקיית ענן לפחות אחת לשבוע.

### שחזור

בטבלת הגיבויים כל שורה מציגה את התאריך, מה יש בפנים (כמה חברים, כמה קבלות), את **סך היתרות**, ואת תוצאת בדיקת החתימה:

- **תקין** – הקובץ תואם לחתימה שנשמרה איתו.
- **פגום** – הקובץ השתנה או ניזוק. **המערכת לא תיתן לשחזר ממנו כלל.**

לחיצה על **שחזור** פותחת אישור שדורש להקליד את המילה `שחזר`. לפני ההחלפה המערכת **יוצרת אוטומטית גיבוי של המצב הנוכחי** – כך שגם שחזור בטעות הוא הפיך. אחרי השחזור המסך נטען מחדש עם הנתונים המשוחזרים – היישום לא נסגר.

### ייצוא כל הנתונים

הכפתור **ייצוא כל הנתונים ל-Excel** מפיק קובץ אחד עם גיליון לכל ישות: חברים, חיובי נדר, תשלומי נדר, תרומות, הוצאות, קבלות, מאזן חודשי, רשימות ערכים, הגדרות ויומן ביקורת. סכומים בשקלים.

### תיקיית ארכיון הקבלות

בהגדרות → מערכת אפשר להצביע על תיקייה אחרת לשמירת קובצי ה-PDF – למשל תיקיית Dropbox או OneDrive, כדי שכל קבלה תסונכרן החוצה מיד עם ההפקה.

- **ריק = תיקיית הנתונים של היישום** (`%APPDATA%
edarimeceipts`).
- **קבלות שכבר הופקו נשארות במקומן.** הנתיב המלא של כל קבלה נשמר איתה, ולכן היא תמשיך להיפתח מהמקום שבו נשמרה. השינוי חל על קבלות חדשות בלבד.
- אם התיקייה אינה קיימת היא תיווצר; אם אין הרשאת כתיבה אליה, השמירה תיכשל **בהגדרות** – ולא ברגע שבו הגבאי עומד מול התורם.
- **הגיבוי עוקב אחרי ההגדרה**: מגבים את התיקייה שהוגדרה, לא את ברירת המחדל.

### ייצוא כל הנתונים

זה לא גיבוי ואי אפשר לשחזר ממנו – זו רשת הביטחון של בית הכנסת: גם אם תחליט מחר לעזוב את המערכת, כל הנתונים שלך בידיך בפורמט שכל אחד קורא.

## 6. תקלות נפוצות

| מה קורה | מה לעשות |
|---|---|
| SmartScreen חוסם את ההתקנה | More info → Run anyway. אין תעודת חתימה כי הפרויקט חופשי |
| הטקסט מופיע משמאל לימין | סגור ופתח את היישום. אם נמשך – דווח כתקלה |
| שכחתי את סיסמת המנהל | אם יש מנהל פעיל נוסף, הוא יכול לאפס. אחרת יש לשחזר מגיבוי שקדם לקביעת הסיסמה |
| "חייב להישאר לפחות מנהל פעיל אחד" | זו הגנה מפני נעילה מחוץ למערכת. הגדר מנהל אחר לפני ההשבתה |
| רוצה להתחיל מחדש לגמרי | סגור את היישום, מחק את `%APPDATA%\nedarim`, פתח שוב |

## 7. הערות למי שמריץ מהקוד

```bash
npm install
npm run dev      # הרצה בפיתוח
npm run check    # בדיקת טיפוסים ו-lint
npm test         # בדיקות
npm run build    # יצירת ההתקנה ב-dist/
```

התקנה אחת = בית כנסת אחד. אין ריבוי ארגונים ואין בורר ארגון: מזהה הארגון הוא בסיס הנתונים עצמו. אין ערך עסקי קשיח בקוד – שם בית הכנסת, מספור הקבלות, השנה הכספית ורשימות הערכים כולם מוגדרים במסך ההגדרות.
